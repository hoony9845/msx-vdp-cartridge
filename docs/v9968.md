# V9968 + geo3d 모드

같은 카트리지로 **V9990**(GFX9000) 대신 HRA!의 **V9968**(MSX2++용 VDP, V9958 상위 호환)과
3D 보조 프로세서 **geo3d v2.0**을 에뮬레이션한다. 어느 칩을 쓸지는 펌웨어 설정으로 고른다.

## 칩 선택

| 방법 | 설명 |
|---|---|
| 빌드 기본값 | `cmake -S firmware -B build-fw -DMSX_VDP_DEFAULT=V9968` (생략하면 `V9990`) |
| USB 시리얼 | `chip v9968` / `chip v9990` 입력: 플래시 마지막 섹터에 저장하고 재부팅. `chip`만 입력하면 현재 칩을 보여 준다 |

- 플래시를 쓰는 동안에는 XIP가 멈춘다. 그래서 명령을 받으면 선택만 워치독 스크래치 레지스터에 남기고 재부팅한다. 플래시 기록은 부팅 직후 다른 코어와 영상 출력이 시작되기 전에 한다.
- 저장된 값이 없으면 빌드 기본값을 쓴다.
- V9968 모드는 PSRAM이 필요 없다. VRAM 256KB를 내부 SRAM에 둔다.

## 포트

V9968 카트리지의 8포트 블록(오프셋 0–7)을, 디코딩된 포트의 하위 니블 8–F에 둔다.

| 니블 | 오프셋 | 장치 |
|---|---|---|
| 8–C | 0–4 | V9968 Port#0–#4 (VRAM, 제어/상태, 팔레트, 간접 레지스터, 인터럽트 제어) |
| D | 5 | geo3d 인덱스 쓰기 / 상태 읽기 |
| E | 6 | 비어 있음 (읽으면 FFh) |
| F | 7 | geo3d 데이터 |

- **지금 PCB**는 74HCT688이 A7–A4 = 0110으로 고정 디코딩한다. 그래서 V9968은 **68h–6Ch**, geo3d는 **6Dh/6Fh**에 보인다.
  - 소프트웨어의 VDP 기준 포트를 68h로 바꾸면 동작한다. geo3d 데모 소스의 `VDP_BASE` 같은 것이다.
- 원래 카트리지와 같은 **88h–8Fh**로 받으려면, 74HCT688의 Q 입력을 A7–A4 = 1000으로 다시 묶으면 된다. 펌웨어는 바꿀 필요가 없다.
- 이 PCB는 선택된 범위의 읽기에 항상 응답한다. 그래서 오프셋 6(원래 카트리지가 MegaRAM용으로 비워 둔 8Eh)도 FFh로 응답한다.

## 구현 범위

| 영역 | 내용 |
|---|---|
| 포트/레지스터 | R#0–R#27, R#32–R#58, S#0–S#9, Port#4 (LockExtReg, CI/LI/FI), R#20/R#21 잠금, V58(V9958 호환, A17 마스크), 256KB VRAM, 주소 자동 증가 규칙 |
| 화면 | TEXT1/2(블링크), MULTICOLOR, GRAPHIC1–7, YJK/YAE, EPAL(256색 15비트 팔레트), G6/G7 VRAM 인터리브, R#23, R#26/R#27 가로 스크롤(SP2, MSK), R#18 세로 보정, 짝/홀 페이지, FIL |
| 스프라이트 | 모드 1/2 (CC/IC/EC, S16, 우선순위 셔플), 모드 3 (64장, 줄당 16장, GRAPHIC4 페이지에서 확대·축소, 상하/좌우 반전, 팔레트 세트, 25/50/75% 반투명), 5S·충돌 플래그와 좌표 |
| 커맨드 | HMMC, YMMM, HMMM, HMMV, LMMC, LMCM, LMMM, LMMV, LINE, SRCH, PSET, POINT, STOP, **LRMM**(회전 복사, 창, XHR), **LFMC/LFMM**(폰트 그리기), FG4, HS(고속) |
| 인터럽트 | 프레임, 라인(ILNS), 커맨드 완료(CEIE) |
| geo3d v2.0 | 레지스터 창 전체, 즉시 모드, 정점/변/면/텍스처 RAM 1024개씩, 변환·투영, 클리핑, 은면 제거, 조명, 페인터 정렬, LINE/LRMM 명령 발행, VFIRST/EFIRST/FFIRST, XCTRL 확장 모드 |

참고 자료:
- V9968: HRA!의 RTL([hra1129/V9968_Cartridge](https://github.com/hra1129/V9968_Cartridge), `fpga/.../src/v9968`)과 프로그래머 매뉴얼.

- 코드는 가져오지 않았다. 동작만 다시 구현했다.

## 검증

| 대상 | 기준 | 결과 |
|---|---|---|
| geo3d | 참조 모델(`gen_scenes.py`, `gen_face_scenes.py`, `gen_tex_scenes.py`, `gen_v2_scenes.py`)이 만든 기대 로그 | 4개 세트, 로그 160,203줄 **완전히 일치**. v2 세트는 공식 README의 77,390줄과 같은 수 |
| 커맨드 엔진 | HRA!의 `vdp_command.v`와 `vdp_command_cache.v`를 iverilog로 시뮬레이션 | 무작위 명령 세트에서 VRAM 256KB와 S#7/BD/S#8 로그 비교 (아래) |
| 화면 출력 | openMSX V9968 포크(buppu3 + alexmoncks `geo3d-v2.0`)를 `tools/compare/v9968`로 비교 | 장면별 도트 단위 비교 (아래) |

### 현재 결과 (2026-10-25)

- **geo3d**: 참조 모델과 완전히 일치 (위 표).
- **커맨드 엔진 vs RTL** (화면 모드 0–9, V9958/V9968 모드, 고속, 명령 80개씩 무작위): 44세트 중 34세트가 VRAM과 로그까지 완전히 일치한다.
  - 나머지 중 다수는 테스트 생성기가 끝나지 않는 LFMM(NX > 1)을 만든 경우다. RTL은 2천만 클럭 제한에 걸려 끊겼다. 생성기는 이미 고쳤다.
  - **아직 원인을 찾지 못한 차이**: GRAPHIC5에서 VRAM 1바이트씩(세트 2140, 2240, 2241), GRAPHIC6 1건(2250), TEXT2 LMCM 로그 1건(2281). 원인을 찾는 중이다.
- **화면 vs openMSX 포크**: 30장면 중 22장면이 도트 단위로 일치한다. 일치한 것은 보정, TEXT1/2, G1–G6, 멀티컬러, CC/IC, TP, R#23, R#18, EPAL, 스프라이트 모드 3, S16, 커맨드, geo3d 와이어프레임/면 채우기다.
  - 아직 다른 장면: GRAPHIC7(스프라이트 색으로 추정), YJK/YAE, 가로 스크롤(MSK/SP2), LRMM, LFMM, geo3d 텍스처.
  - 어느 쪽 문제인지(우리 코어인지, openMSX 포크인지)는 아직 판단하지 않았다.

openMSX 포크 준비 방법은 `tools/compare/v9968/openmsx_env.sh` 머리말에 있다.
- 창 없이 실행하려면 `SDL_VIDEODRIVER=offscreen`을 쓴다.
- 이 포크는 디버거로 CE를 보여 주지 않는다. 그래서 `wait_ce`는 정해진 시간(에뮬레이션 시간 0.15초)만큼 기다린다.

## RTL과 다르게 한 부분

- **LMCM**은 V9938처럼 (SX, SY)를 읽는다.
  - RTL은 (DX, DY)를 읽는다. 게다가 DY는 진행하지 않고, 카운터를 갱신하기 전 좌표를 한 번 더 읽어서 결과가 한 픽셀씩 밀린다. 그래서 여러 줄을 읽는 LMCM은 RTL에서 제대로 동작하지 않는다.
  - 검증할 때는 `cmd.rtl_lmcm`을 켜서 RTL 동작을 그대로 재현한다.
- **TEXT1/2**는 openMSX(V9938 실기 기준)처럼 왼쪽 테두리를 9도트로 둔다.
- 다음 RTL 동작은 그대로 재현했다. 하드웨어도 같게 동작하기 때문이다.
  - **NX > 1인 LFMM**은 끝나지 않는다. 첫 글자 칸이 끝날 때 NX 레지스터를 카운터로 덮어쓰기 때문이다.
  - NX = 1이면 마지막 줄은 첫 픽셀만 그린다.
  - DX가 화면 밖으로 나가는 LFMM도 끝나지 않는다.

## 한계

- **커맨드 속도**는 RTL의 대기 상수(호환 속도에서 접근마다 {40, 2'b11} 클럭)와 고속 모드 실측값(LINE 약 7, LRMM 약 12클럭/픽셀)을 85.9MHz 기준으로 흉내 낸다. 클럭 단위까지 정확하지는 않다.
- **HR**은 줄의 절반 동안 1이다. DVI 두 줄이 VDP 한 줄이기 때문이다.
- **줄 타이밍**: V9968 모드에서는 n번째 줄을 n−1번째 줄 출력의 후반부에 그린다.
  - 그래서 라인 인터럽트 처리 루틴이 바꾼 레지스터는 보통 다음 줄부터 반영된다. 처리에 쓸 수 있는 시간은 약 31µs다.
  - 줄 중간에서 바뀌는 효과는 표현하지 않는다.
- **인터레이스**(IL+EO, FIL)는 두 필드를 합친 424줄 순차 화면으로 보여 준다.
- **R#18 가로 보정**은 구현하지 않았다. RTL에도 없다.
- **geo3d** 계산은 에뮬레이션 시간을 쓰지 않는다(openMSX와 같음). 명령은 커맨드 엔진이 빌 때마다 하나씩 넣는다.

# 하드웨어 결선 (프로토타입: Pimoroni Pico Plus 2)

MSX 슬롯은 5V, RP2350은 3.3V이므로 모든 신호를 74LVC 계열(3.3V 전원, 5V 입력 허용)로 버퍼링한다.

```
MSX 슬롯 (5V)                                  Pico Plus 2 (3.3V)
──────────────                                 ──────────────────
A7 A6 A5 A4 /IORQ /M1 ─► U3 74HCT688 ─ /CS ─┐
                                            ├─► U2 74LVC245 (A→B 고정) ─► GP20 (/CS)
A0-A3, /RD, /WR, /RESET ────────────────────┘                          ─► GP0-3, GP21, GP22, GP26
D0-D7 ◄──────────────► U1 74LVC245 (DIR=/RD, /OE=/CS) ◄──────────────► GP4-11
/INT  ◄─ U4 74LVC07 ◄─ GP27
/WAIT ◄─ U4 74LVC07 ◄─ GP28
/BUSDIR ◄─ U4 74LVC07 ◄─ U5 74HCT32 (/CS OR /RD)
+5V ──► D1 B5819W (쇼트키) ──► VSYS
/CS ──► R9 10k ──► 3V3 (MSX 전원이 꺼진 채 USB로만 켜졌을 때 U1을 꺼 둠)
                                               GP12-19 ─► R1-R8 270Ω ─► HDMI(DVI) 커넥터
```

## 부품

| 부품 | 전원 | 역할 |
|---|---|---|
| U1 74LVC245 | 3.3V | 데이터 버스 양방향 버퍼. A=MSX, B=RP2350. `DIR` = `/RD` (읽기일 때 B→A), `/OE` = `/CS` |
| U2 74LVC245 | 3.3V | 주소/제어 입력 버퍼. `DIR`=H 고정, `/OE`=GND |
| U3 74HCT688 | 5V | 포트 디코더. `P` = {A7, A6, A5, A4, /IORQ, /M1}, `Q` = {0, 1, 1, 0, 0, 1}, 남는 입력은 `P=Q`로 묶고 `/G`=GND. 출력 `/P=Q` → `/CS` |
| U4 74LVC07 | 3.3V | 오픈 드레인 출력 (`/INT`, `/WAIT`, `/BUSDIR`). GPIO high = 해제 |
| U5 74HCT32 | 5V | `/BUSDIR` = `/CS` OR `/RD`: 이 카트리지가 읽기에 응답할 때 low |

- `/M1`을 디코딩에 넣는 이유: 인터럽트 응답 사이클(`/M1`과 `/IORQ`가 동시에 low)에 응답하면 안 되기 때문이다.
- `/BUSDIR`: 슬롯 쪽에 데이터 버퍼가 있는 기종은 I/O 읽기에 응답하는 카트리지가 이 신호를 low로 내려야 데이터가 CPU 쪽으로 전달된다.
- 디코더가 A4–A7만 보기 때문에 0x68–0x6F도 선택된다. 이 포트를 읽으면 0xFF를 응답한다.
  다른 장치와 충돌하면 0x60–0x67만 응답하도록 펌웨어(`bus.c`)를 수정한다.

## MSX 카트리지 슬롯 핀 (사용하는 것만)

| 핀 | 신호 | 핀 | 신호 |
|---|---|---|---|
| 7 | /WAIT | 8 | /INT |
| 9 | /M1 | 10 | /BUSDIR |
| 11 | /IORQ | 13 | /WR |
| 14 | /RD | 15 | /RESET |
| 28, 27, 30, 29 | A0, A1, A2, A3 | 32, 31, 22, 21 | A4, A5, A6, A7 |
| 34, 33, 36, 35 | D0, D1, D2, D3 | 38, 37, 40, 39 | D4, D5, D6, D7 |
| 45, 47 | +5V | 41, 43 | GND |

> 실제 PCB를 설계하기 전에 MSX 슬롯 핀 배치를 공식 문서와 다시 대조할 것.

## RP2350 GPIO 할당 (`firmware/src/board_pins.h`)

| GPIO | 신호 | GPIO | 신호 |
|---|---|---|---|
| 0–3 | A0–A3 | 20 | /CS (디코딩 결과) |
| 4–11 | D0–D7 | 21 | /RD |
| 12/13 | DVI D0 +/− | 22 | /WR (예약) |
| 14/15 | DVI CLK +/− | 26 | /RESET 입력 |
| 16/17 | DVI D2 +/− | 27 | /INT 출력 |
| 18/19 | DVI D1 +/− | 28 | /WAIT 출력 (예약) |
| 47 | PSRAM CS (보드 내장) | | |

- PIO는 A0–A3 바로 뒤에 D0–D7이 이어진다고 가정한다(`in pins, 12`). 핀을 바꿀 때 이 순서를 유지할 것.
- HSTX는 GPIO 12–19에만 나온다.
- HDMI 커넥터는 카트리지 PCB에 직접 실장했다. 각 TMDS 선에 270Ω 직렬 저항을 넣어 50Ω 종단 기준 약 500mV 진폭이 나오게 했다.
  레인 배치는 `board_pins.h`의 `PIN_DVI_*`와 같다.
- 회로의 원본은 `hardware/gen/design.py`다. 이 표와 다르면 design.py가 맞다.

## RP2350B 코어 보드를 쓰는 경우

- GPIO 48개가 모두 나와 있으므로 핀맵은 그대로 쓸 수 있다.
- PSRAM이 없는 보드가 많다. APS6404L(QSPI PSRAM)을 QSPI 버스에 달고 CS를 XIP_CS1 기능이 있는 핀(GPIO 0, 8, 19, 47 — RP2350 데이터시트의 GPIO 기능표에서 확인할 것. 0과 19는 이미 버스와 DVI에 쓰고 있으므로 47 권장)에 연결한다.
  그 다음 `-DPICO_BOARD=<보드> -DV9990_PSRAM_CS_PIN=<GPIO>`로 빌드한다.
